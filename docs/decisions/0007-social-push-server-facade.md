# ADR 0007: 소셜 푸시는 인증된 Edge Function에서 발송한다

- 상태: 승인됨
- 날짜: 2026-07-14

## 결정

- 친구 요청 생성과 1:1 챌린지 초대 생성은 앱에서 `social-mutations` Edge Function을 호출한다.
- 함수는 호출자의 JWT를 검증하고, 호출자 RLS 문맥으로 기존 RPC를 실행한다. 이후에만 서버 전용 권한으로 수신자의 활성 Expo 푸시 토큰을 조회해 발송한다.
- 푸시 본문은 기기별 locale로 서버에서 만들며, 계획 제목·메모·친구 코드·토큰을 포함하지 않는다. payload에는 안정적인 route와 entity ID만 넣는다.
- 기기 토큰은 앱 설치별 임의 ID의 SHA-256 해시와 함께 저장한다. 동일 기기에서 다른 계정이 로그인하면 이전 등록을 교체하며, 로그아웃 시 현재 등록을 비활성화한다.
- Expo가 즉시 `DeviceNotRegistered`를 반환한 토큰은 서버에서 비활성화한다. 푸시 영수증을 15분 뒤 주기적으로 수집하는 작업은 발송량이 늘어난 뒤 별도 scheduler 범위로 보강한다.

## 결과

- 앱 번들에는 서비스 역할 키나 Expo 발송 자격증명이 들어가지 않는다.
- 기존 소셜 RPC의 원자적 도메인 검증은 유지되지만, 푸시 발송은 성공한 소셜 변경 뒤의 best-effort 작업이다. 발송 실패가 친구 요청이나 챌린지 초대를 되돌리지는 않는다.
- 사용자가 앱을 제거해 즉시 발송 ticket에 반영되지 않는 경우는 다음 영수증 수집 보강 전까지 토큰이 남아 있을 수 있다.
