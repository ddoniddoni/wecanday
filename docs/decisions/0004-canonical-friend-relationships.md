# ADR 0004: canonical pair 기반 친구 관계

- 상태: 승인됨
- 날짜: 2026-07-14

## 배경

두 사용자가 비슷한 시점에 서로에게 친구 요청을 보내거나, 거절·취소 후 다시 요청할 수 있다. 요청 방향만으로 관계를 저장하면 같은 사용자 쌍에 중복 관계가 생길 수 있다.

## 결정

- `friendships`는 요청자·수신자와 별도로 정렬된 두 사용자 ID의 unique canonical pair를 저장한다.
- 같은 쌍의 최초 요청은 `pending`으로 만든다. 반대 방향의 pending 요청이 있으면 별도 행을 만들지 않고 `accepted`로 원자적으로 전환한다.
- 수신자는 pending 요청을 `accepted` 또는 `declined`로 응답하고, 요청자는 pending 요청을 `cancelled`로 전환할 수 있다. 거절·취소·삭제 상태에서는 같은 canonical pair를 재사용해 새 pending 요청을 만든다.
- 관계의 직접 쓰기는 클라이언트에 허용하지 않는다. own-row RLS 조회와 인증된 RPC만 사용하며, RPC는 차단 관계를 먼저 검사한다.

## 결과

- 사용자 쌍마다 DB 수준에서 관계 행이 최대 하나이므로 중복 요청과 동시 요청 경쟁 조건을 막는다.
- 요청함 RPC는 표시 이름과 아바타 시드만 반환하며 이메일, 공개 코드, 루틴 정보는 노출하지 않는다.
- 후속 T-404는 같은 관계 모델에서 차단·친구 삭제를 원자적으로 확장한다.
