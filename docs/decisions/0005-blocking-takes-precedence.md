# ADR 0005: 차단은 친구 관계보다 우선한다

- 상태: 승인됨
- 날짜: 2026-07-14

## 배경

친구 요청, 수락, 취소와 차단이 서로 다른 기기에서 거의 동시에 실행될 수 있다. 차단 뒤에 pending 또는 accepted 관계가 남으면 검색·초대 차단 규칙을 위반할 수 있다.

## 결정

- 친구 요청, 응답, 취소, 삭제, 차단은 사용자 쌍마다 같은 transaction-scoped advisory lock을 획득한다.
- 차단 RPC는 차단 행을 upsert하고 해당 쌍의 pending·accepted 관계를 같은 트랜잭션에서 삭제한다.
- 친구 요청과 수락 RPC는 잠금 뒤 양방향 차단 관계를 다시 검사한다. 차단이 있으면 `USER_BLOCKED`로 실패한다.
- 차단 목록과 친구 목록은 각각 최소 프로필만 반환하는 인증 RPC로 제공한다. `user_blocks` 테이블의 직접 클라이언트 권한은 부여하지 않는다.

## 결과

- 차단과 요청/수락 경쟁에서 차단이 최종 상태를 결정하며, 차단된 사용자는 요청·검색·후속 초대의 기반 관계를 만들 수 없다.
- 차단 해제는 이전 친구 관계를 복구하지 않는다. 필요한 경우 양쪽이 새 친구 요청을 보내야 한다.
