# WeCanDay 작업 단위 개발 기획서

> 상태: 2026-07-13 기준 초안  
> 기준 문서: [`PRD.md`](../../PRD.md), [`AGENTS.md`](../../AGENTS.md)

## 목적

기능을 큰 묶음으로 한 번에 만들지 않는다. 아래의 **Task 하나는 사용자가 직접 확인할 수 있는 한 가지 변화**만 포함한다. 구현 중 새 데이터 모델, 네이티브 모듈, 외부 서비스 설정이 필요한 범위가 드러나면 현재 Task를 끝내고 다음 Task로 분리한다.

### 작업 규칙

- 한 Task는 화면 하나 또는 도메인 규칙 하나를 넘지 않는다.
- 데이터베이스 변경은 해당 Task에만 필요한 migration, RLS, SQL 테스트를 함께 둔다.
- 완료 전 `npm run lint`, `npm run typecheck`, `npm run test`를 실행한다.
- GitHub CI와 React Doctor는 사용자가 다시 요청할 때까지 실행하지 않는다.
- 네이티브 모듈을 추가한 Task만 Android 번들 또는 development build를 확인한다.
- 작업 순서는 우선순위다. 사용자가 원하는 기능은 언제든 앞당길 수 있다.

## M2 — 핵심 루틴 마무리

### T-201 · Android에서 오늘 체크인 수동 확인 — 완료

- 목적: 실제 기기에서 오늘 목록, 완료·취소, 앱 재시작 후 상태를 확인한다.
- 포함: 기존 기능의 수동 QA와 발견 버그 수정만.
- 완료 조건:
  - 루틴 생성 후 오늘 목록에 보인다.
  - 완료와 취소가 즉시 반영된다.
  - 앱 재시작 뒤 완료 상태가 유지된다.
- 제외: 새 UI, 스트릭, 알림.
- 구현 결과: Android 에뮬레이터에서 최신 development build를 설치해 계획·오늘 목록 표시, 완료·취소, 앱 재시작 뒤 체크인 상태 유지를 확인했다. 데일리 스트릭 조회가 실패했을 때 오늘 체크인 흐름 전체가 막히던 버그를 수정했다.

### T-202 · 계획 목록 읽기 화면 — 완료

- 목적: 사용자가 만든 계획을 목록에서 확인한다.
- 포함: 활성/일시정지/보관 상태 표시, 빈 상태, 계획 만들기 진입 버튼.
- 완료 조건: 내 계획만 보이고, 계획이 없을 때 다음 행동을 안내한다.
- 구현 결과: RLS가 적용된 `plans` 조회, 상태 표시, loading·empty·재시도 상태, 새 계획 만들기 진입을 추가했다.
- 제외: 수정·보관 동작.

### T-203 · 기존 계획에 루틴 추가 — 완료

- 목적: 한 계획에 두 번째 이후의 루틴을 추가한다.
- 포함: 행동 제목, 요일 선택, 서버 무료 4개 제한 오류 안내.
- 완료 조건: 추가한 항목이 계획 목록과 오늘 목록에 반영된다.
- 제외: Premium 결제 화면.
- 구현 결과: 계획을 선택해 행동·요일을 추가할 수 있고, 추가 뒤 활성 루틴 수와 오늘 목록에 반영된다. 서버 RPC는 소유 계획과 입력을 재검증하며 기존 4개 제한을 적용한다.

### T-204 · 루틴 제목·요일 수정 — 완료

- 목적: 생성한 루틴의 행동 제목과 수행 요일을 바꾼다.
- 포함: 입력 검증, 저장·실패 상태, 오늘 목록 재반영.
- 완료 조건: 수정한 요일에만 해당 루틴이 오늘 목록에 표시된다.
- 제외: 시작일/종료일·알림 시각 수정.
- 구현 결과: 오늘 목록에서 루틴별 수정 화면으로 진입해 제목과 수행 요일을 바꿀 수 있다. 서버 RPC가 소유자·제목·요일을 재검증하며, 저장 뒤 오늘 목록으로 돌아간다.

### T-205 · 루틴 일시정지와 재개 — 완료

- 목적: 잠시 쉬는 루틴을 오늘 목록과 스트릭 예정일에서 제외한다.
- 포함: 일시정지/재개 버튼, 상태 문구, 서버 4개 제한 재검증.
- 완료 조건: 일시정지 즉시 오늘 목록에서 사라지고, 재개 시 제한을 넘으면 안내한다.
- 제외: Premium 해제 처리.
- 구현 결과: 루틴 수정 화면에서 일시정지·재개할 수 있고, 계획 관리 화면에서 일시정지된 루틴도 다시 열 수 있다. 재개는 서버의 활성 4개 제한을 적용하며, 상태 변경 이력은 이후 스트릭 계산에 사용하도록 보존한다.

### T-206 · 계획·루틴 보관 — 완료

- 목적: 더 이상 진행하지 않는 항목을 삭제하지 않고 숨긴다.
- 포함: 보관 확인, 보관 목록, 과거 체크인 유지.
- 완료 조건: 보관한 항목은 오늘 목록에서 사라지고 과거 데이터는 남는다.
- 제외: 영구 삭제.
- 구현 결과: 루틴·계획 보관 전 확인 단계를 제공한다. 계획 보관은 포함된 진행 중·일시정지 루틴을 원자적으로 보관하고, 보관된 계획·루틴은 계획 관리 목록에서 상태와 함께 확인할 수 있다. 체크인 행은 삭제하지 않는다.

### T-207 · 루틴 데이 종료 시각 표시 — 완료

- 목적: 홈에서 현재 루틴 데이와 종료까지 남은 시간을 보여준다.
- 포함: `routine-day` 도메인 API 사용, 분 단위 갱신, locale 시간 형식.
- 완료 조건: 하루 시작 시각과 시간대에 맞는 종료 시각이 표시된다.
- 제외: 스트릭·알림.
- 구현 결과: 홈에서 사용자의 시간대 기준 종료 시각과 남은 시간을 표시한다. 남은 시간은 다음 분 경계마다 갱신하며, 계산과 locale 시간 포맷은 `routine-day` 도메인 API로 분리했다.

## M2 — 스트릭과 알림

### T-208 · 항목 스트릭 순수 도메인 함수 — 완료

- 목적: 예정일·완료 기록으로 항목별 연속 완료 횟수를 계산한다.
- 포함: 예정되지 않은 날, 실패일, 일시정지 규칙 테스트.
- 완료 조건: UI와 DB에 의존하지 않는 함수와 PRD 필수 단위 테스트가 있다.
- 제외: 화면 표시.
- 구현 결과: 루틴 요일, 완료한 루틴 데이, 상태 이력, 기준 루틴 데이를 입력받아 항목 스트릭을 계산하는 순수 도메인 함수를 추가했다. 일시정지 기간과 예정되지 않은 날은 스트릭을 끊지 않는다.

### T-209 · 데일리 스트릭 순수 도메인 함수 — 완료

- 목적: 해당 루틴 데이의 모든 예정 항목 완료 여부로 데일리 스트릭을 계산한다.
- 포함: 예정 항목 0개, 휴식일, 완료/미완료 케이스.
- 완료 조건: 예정 항목이 없는 날은 증가·종료 모두 하지 않는다.
- 제외: 스트릭 보호권.
- 구현 결과: 루틴 데이별 예정 항목과 완료 항목을 입력받아 데일리 스트릭을 계산하는 순수 도메인 함수를 추가했다. 예정 항목이 없는 날은 중립으로 건너뛰고, 예정 항목 하나라도 미완료인 날부터 새 스트릭을 계산한다.

### T-210 · 홈 스트릭·완료율 표시 — 완료

- 목적: 오늘 화면에 데일리 스트릭과 `완료/예정` 진행률을 표시한다.
- 포함: loading·empty 상태, 접근 가능한 텍스트 요약.
- 완료 조건: 체크인 직후 수치가 갱신된다.
- 제외: 주간·월간 통계.
- 구현 결과: 홈에 오늘 완료/예정 진행률과 데일리 스트릭 요약을 추가했다. 오늘이 진행 중이면 이전 완료 스트릭을 유지하고, 마지막 예정 항목을 체크인하면 스트릭을 즉시 증가시킨다. 상태 이력 조회 인덱스를 추가해 사용자별 스트릭 계산 조회를 지원한다.

### T-211 · 알림 권한 안내 — 완료

- 목적: 첫 루틴이 만들어진 뒤에만 알림 권한을 요청한다.
- 포함: 가치 설명 화면, 거절 상태, Android 권한 흐름.
- 완료 조건: 온보딩이나 로그인 직후에는 권한을 묻지 않는다.
- 제외: 실제 알림 예약.
- 구현 결과: 첫 계획·루틴 생성 뒤에만 알림의 용도를 설명하고, 사용자가 선택할 때 Android 알림 채널 생성 후 시스템 권한을 요청한다. 나중에 선택과 권한 거절 모두 정상적으로 홈으로 이어지며, 선택 결과는 사용자별 로컬 설정에 기록한다.

### T-212 · 루틴 1개 로컬 알림 예약 — 완료

- 목적: 사용자가 정한 알림 시각에 한 루틴을 알린다.
- 포함: 알림 시각 저장, 로컬 예약, 취소.
- 완료 조건: 완료·일시정지한 항목에는 불필요한 알림이 남지 않는다.
- 제외: 스트릭 위험 알림.
- 구현 결과: 루틴별 선택 알림 시각을 저장하고 선택한 요일마다 고정 identifier로 로컬 주간 알림을 예약한다. 완료·취소·일시정지·보관에 맞춰 예약을 취소하거나 복원하며, 알림 내용은 한국어·영어로 현지화하고 잠금 화면에는 루틴 제목을 넣지 않는다.

### T-213 · 시간대·일정 변경 시 알림 재예약 — 진행 중

- 목적: 시간대, 하루 시작 시각, 요일 변경 뒤 알림이 정확한 현지 시각을 유지한다.
- 포함: 기존 예약 취소와 새 예약 생성.
- 완료 조건: 중복 알림 identifier가 생기지 않는다.
- 현재 결과: 프로필의 시간대·하루 시작 시각·언어가 바뀌거나 앱 언어가 변경되면, 알림 시각을 선택한 활성 루틴의 기존 예약을 identifier 기준으로 취소한 뒤 다시 생성한다. Android의 반복 주간 트리거는 기기 현지 시간으로만 동작하므로, 기기 시간대와 다른 프로필 시간대를 지속 보장하는 방식은 별도 설계가 필요하다. MVP 우선순위에 따라 이 설계는 보류한다.

## M3 — 동반자, 테마, 통계

### T-301 · 기본 2D 동반자 에셋과 상태 모델 — 완료

- 목적: 오리지널 2D 동반자를 기본/응원/완료 상태로 표시한다.
- 포함: 에셋 key와 상태 모델 분리, 접근성 설명.
- 완료 조건: 타사 캐릭터를 사용하지 않고, 상태가 텍스트로도 설명된다.
- 구현 결과: 완료율에 따라 휴식/응원/모두 완료 상태가 바뀌는 동반자 히어로와 진행률을 오늘 화면에 추가했다.
- 제외: 애니메이션·경험치.

### T-302 · 체크인 완료 동반자 반응 — 완료

- 목적: 체크인 직후 짧은 완료 반응을 보여준다.
- 포함: 동작 줄이기 설정 존중, 선택적 햅틱.
- 완료 조건: 애니메이션 실패가 체크인 저장을 막지 않는다.
- 구현 결과: 체크인을 낙관적으로 완료할 때 동반자가 짧게 반응한다. 시스템 동작 줄이기 설정에서는 정적인 상태로 유지하며, 햅틱은 별도 선택 설정 작업으로 남긴다.

### T-303 · 테마 선택 화면 — 완료

- 목적: 시스템/라이트/다크/기본 픽셀 테마를 사용자가 고른다.
- 포함: 설정 저장, 즉시 반영.
- 완료 조건: 모든 테마에서 오늘 목록의 완료 상태를 색상 외 요소로도 구분한다.
- 구현 결과: 오늘 화면에서 시스템·라이트·다크·픽셀 테마를 선택할 수 있다. 선택은 즉시 반영되고 본인 프로필의 `theme_id`에 저장되며, 저장 실패 시 이전 테마로 안전하게 되돌린다.

### T-304 · 주간 통계 — 완료

- 목적: 최근 7개 루틴 데이의 완료율과 데일리 스트릭을 보여준다.
- 포함: 예정 항목 0개인 날 처리, 빈 상태.
- 완료 조건: 집계 기준은 기기 자정이 아니라 저장된 `routine_day`다.
- 구현 결과: 최근 7개 저장된 루틴 데이의 완료율·일별 진행·휴식일·현재/최고 데일리 스트릭을 보여준다. 완료율은 완료한 예정 항목 수를 전체 예정 항목 수로 나누며, 예정 항목이 없는 날은 분모에서 제외한다. 오늘 화면의 주간 통계 버튼으로 진입할 수 있고, 로딩·재시도·빈 상태와 접근성 요약을 제공한다.

### T-305 · 월간 통계 — 완료

- 목적: 한 달 완료율과 계획별 완료율을 보여준다.
- 포함: 월 이동, 빈 상태, 접근 가능한 요약.
- 완료 조건: 계획 제목 원문을 외부 로그에 남기지 않는다.
- 구현 결과: 저장된 `routine_day` 기준으로 선택한 월과 지난달을 함께 집계한다. 월간 캘린더에는 일별 완료율·휴식일을 보여주며, 완료한 루틴 데이 수·계획별 완료율·지난달 대비를 제공한다. 월 이동은 미래 달을 막고, 로딩·재시도·빈 상태와 스크린 리더 요약을 제공한다.

### T-306 · 연간 통계 — 완료

- 목적: 12개월 히트맵, 총 체크인 수, 최고 연속 기록을 보여준다.
- 포함: 연도 선택, 큰 목록의 효율적 렌더링.
- 완료 조건: 대량 기록에서도 홈 진입을 느리게 하지 않는다.
- 구현 결과: 선택 연도 범위의 체크인만 조회해 12개월 히트맵, 총 체크인 수, 해당 연도의 최고 데일리 스트릭, 월별 완료율 추세를 제공한다. 연도 이동은 미래 연도를 막고, 연간 화면 데이터는 사용자가 진입했을 때만 불러온다.

## M4 — 친구와 챌린지

### T-401 · 내 고유 코드 복사·공유 — 완료

- 목적: 프로필에서 12자리 코드를 안전하게 복사·공유한다.
- 포함: 복사 버튼, 시스템 공유 시트, 접근성 안내.
- 완료 조건: 이메일이나 전체 프로필은 공유하지 않는다.
- 구현 결과: 오늘 화면의 내 친구 코드 카드에서 12자리 코드를 복사하거나 Android 시스템 공유 시트로 보낼 수 있다. 공유 메시지에는 코드 외 프로필·이메일·루틴 정보가 포함되지 않으며, 복사·공유 실패 상태와 접근성 라벨을 제공한다.

### T-402 · 정확한 코드 친구 검색 RPC — 완료

- 목적: 12자리 전체 코드로만 최소 프로필을 찾는다.
- 포함: 형식 검증, 자기 자신·차단 관계 제외, rate limit 설계.
- 완료 조건: profiles 전체 목록을 클라이언트에 열지 않는다.
- 구현 결과: 12자리 Base62 형식을 앱과 RPC에서 모두 검증하고, 인증 사용자만 호출 가능한 최소 프로필 검색 RPC를 원격 Supabase에 적용했다. 본인·양방향 차단 관계를 제외하며, 유효한 코드 조회는 사용자별 분당 10회로 제한한다. `profiles` 직접 조회는 본인 행으로 계속 제한되고, 검색 화면은 표시 이름과 아바타 미리보기만 보여 준다.

### T-403 · 친구 요청·수락·거절 — 완료

- 목적: 두 사용자가 중복 없이 친구 관계를 만든다.
- 포함: 요청 상태, own-row RLS, 서버 원자성.
- 완료 조건: 같은 사용자 쌍에 중복 관계가 생기지 않는다.
- 구현 결과: canonical pair unique 제약을 가진 `friendships`와 own-row RLS를 추가했다. 코드 검색 결과에서 요청을 보내고, 요청함에서 수락·거절·취소할 수 있다. 상호 pending 요청은 자동 수락으로 합쳐지며, 차단 관계는 서버에서 요청보다 먼저 거부한다.

### T-404 · 친구 삭제·차단 — 완료

- 목적: 관계 해제와 차단을 안전하게 처리한다.
- 포함: 차단 우선 규칙, 검색·요청 차단, RLS 테스트.
- 완료 조건: 차단된 사용자는 요청·초대를 보낼 수 없다.
- 구현 결과: 친구 목록에서 삭제·차단을, 차단 목록에서 차단 해제를 제공한다. 차단은 같은 사용자 쌍의 pending/accepted 관계를 원자적으로 제거하며, 요청·수락 RPC에도 pair lock과 차단 재검사를 적용해 차단이 우선하도록 했다.

### T-405 · 1:1 기본 챌린지 생성 — 완료

- 목적: 친구와 기간·요일이 있는 공동 목표를 만든다.
- 포함: 초대/수락 상태, 각자 루틴 생성, 무료 제한 포함.
- 완료 조건: 각 사용자의 시간대·루틴 데이를 독립적으로 적용한다.
- 구현 결과: 친구 목록에서 기간·요일을 지정해 1:1 챌린지 초대를 만들고, 받은 초대를 수락·거절할 수 있다. 수락 시 각 사용자의 개별 계획과 루틴이 생성되며, 시작일 기본값은 생성자의 현재 루틴 데이를 사용한다. 서버는 친구·차단 관계와 무료 활성 루틴 제한을 최종 검증한다.

### T-406 · 소셜 푸시 기초 — 완료

- 목적: 친구 요청과 챌린지 초대를 푸시로 알린다.
- 포함: 기기 토큰 upsert, locale, 만료 토큰 비활성화.
- 완료 조건: 알림 payload에 민감한 계획 제목을 넣지 않는다.
- 구현 결과: Expo 푸시 토큰을 사용자·기기·locale별로 upsert하고, 친구 요청·챌린지 초대를 인증된 Edge Function을 통해 발송한다. 잠금 화면에는 계획 제목·메모를 넣지 않으며 `DeviceNotRegistered` 토큰은 비활성화한다.

## M5 — Premium과 출시 준비

### T-501 · RevenueCat 연결과 Premium entitlement

- 목적: 로그인한 Supabase 사용자와 RevenueCat 사용자를 안전하게 연결한다.
- 포함: `premium` entitlement, 로그인·로그아웃 전환.
- 완료 조건: 클라이언트 상태만으로 서버 제한을 해제하지 않는다.

### T-502 · Google Play 상품·구매 화면

- 목적: 월간/연간 상품과 지역 가격을 Offering에서 표시한다.
- 포함: 구매 시작·성공·취소·대기 상태.
- 완료 조건: 가격을 코드에 하드코딩하지 않는다.

### T-503 · 구매 복원과 구독 만료

- 목적: 구매 복원과 만료 후 4개 제한 동작을 처리한다.
- 포함: 기존 5개 이상 루틴 보존, 새 생성·재활성화만 차단.
- 완료 조건: 만료가 체크인·과거 기록을 막지 않는다.

### T-504 · RevenueCat 웹훅 entitlement mirror

- 목적: 서버가 구독 권한을 최종 판단하게 한다.
- 포함: 웹훅 서명 검증, entitlement 테이블 upsert.
- 완료 조건: 위조된 클라이언트 Premium 값으로 제한을 우회할 수 없다.

### T-505 · 로그아웃·계정 삭제 흐름 — 완료

- 목적: 앱 안에서 계정 삭제를 시작하고 관련 데이터를 삭제 또는 익명화한다.
- 포함: 확인 단계, 세션 종료, 데이터 cascade 정책.
- 완료 조건: 삭제된 코드는 검색되지 않고 토큰을 로그에 남기지 않는다.
- 구현 결과: 계정 화면에서 현재 기기 로그아웃과 별도 2단계 회원 탈퇴를 제공한다. 로그아웃은 기기별 세션·알림·오프라인 대기열을 정리하고, 탈퇴는 인증된 Edge Function이 refresh token을 revoke한 뒤 Auth 사용자를 hard delete한다. 기존 cascade로 프로필·공개 코드·루틴·체크인·친구 관계·푸시 토큰·생성 챌린지를 제거하며 원격 SQL 테스트로 검증했다.

### T-506 · 개인정보·약관·출시 설정 — 진행 중

- 목적: 필수 법적 화면과 Google Play 출시 설정을 준비한다.
- 포함: 개인정보처리방침, 약관, Data Safety 검토, 계정 삭제 URL.
- 완료 조건: 실제 수집 데이터와 스토어 설명이 일치한다.
- 현재 결과: 계정 설정에서 한국어·영어 개인정보처리방침과 이용약관을 각각 열 수 있다. 문구는 Google 로그인, Supabase, Expo Push, 친구 코드, 계정 삭제의 실제 데이터 흐름을 설명하며 연락처·위치·결제 카드 정보를 요청하지 않는다는 점을 명시한다. [`docs/release/google-play-release-checklist.md`](release/google-play-release-checklist.md)에 Data Safety, 공개 정책 URL, 공개 계정 삭제 URL, Google OAuth production 설정 검증 항목을 추가했다.
- 출시 전 차단 항목: 출시 책임자가 법적 사업자 정보·지원 연락처·공개 HTTPS 개인정보처리방침 URL·공개 계정 삭제 URL을 확정하고, 법률 검토 및 Play Console Data Safety 입력을 마쳐야 한다. 이 정보는 임의로 만들지 않는다.

### T-507 · Android Internal Testing 배포

- 목적: Play Console 내부 테스트 트랙에 첫 Android 빌드를 배포한다.
- 포함: EAS Build/Submit, production 환경 변수 확인, 실제 Google 로그인 확인.
- 완료 조건: 내부 테스터가 설치·로그인·첫 체크인을 수행한다.
